# DSH Mobile 使用指南

本文件由 DSH Mobile 安装包放置于共享存储目录，供使用者与 AI 助手按需查阅。
本文件不会被自动加入任何会话上下文。

- Android 设备：文件管理器 → `内部存储/DeepseekHarness/使用指南.md`
- 容器内：`/sdcard/使用指南.md` 或 `/mnt/phone/DeepseekHarness/使用指南.md`

---

## 1. 运行环境说明

本应用（`com.dsh.mobile`）通过 PRoot 在 Android 设备上运行 Debian 13（aarch64）容器。

| 项目 | 说明 |
|---|---|
| 容器内身份 | `uid=0` 由 PRoot 模拟，实际 Android uid 为应用自身；`CapEff=0`，不具备真实特权 |
| 文件系统 | 分为两类：**内部区**（`/root` 等）为 f2fs，具备完整 POSIX 能力；**外部区**（`/storage/emulated/0`，挂载于 `/mnt/phone`、`/root/手机存储`）为 FUSE，挂载参数 `noexec,nosuid,nodev` |
| FUSE 支持 | 读取、写入、追加、删除、重命名、修改 mtime、创建目录 |
| FUSE 不支持 | 硬链接（`EPERM`）、软链接（`EACCES`）、可执行位（`noexec`）、大小写区分（不敏感） |
| 存储映射 | `/sdcard` 指向 `DeepseekHarness/` 子目录；`/mnt/phone` 为完整共享存储 |
| 系统文件 | `/proc/uptime`、`/proc/loadavg` 等由 PRoot 生成静态内容，不反映真实系统状态 |

---

## 2. 工作区

默认工作区位于容器内部目录（f2fs），具备完整 POSIX 能力，git、npm、pnpm 及编译脚本均可直接使用。

判断当前工作区所在文件系统：

```bash
stat -f -c %T <工作区路径>
# 返回 f2fs：内部目录，功能完整
# 返回 fuse：位于共享存储，参考第 2.1 节
```

### 2.1 工作区位于共享存储时的兼容规则

此情况由使用者主动指定。系统会自动采用以下兼容策略，无需向使用者报告问题或要求其变更设置。

| 项目 | 处理方式 |
|---|---|
| 文件写入 | 改用 shell 重定向（`cat > file`、`echo > file`、`tee file`）。`write`/`edit` 工具依赖硬链接，在 FUSE 上会返回 `EPERM` |
| git | 使用 `git init --separate-git-dir=$HOME/.gitstore/<名称> .`，并设置 `core.symlinks=false`、`core.fileMode=false`、`core.ignorecase=true` |
| npm | 添加 `--no-bin-links` 参数 |
| pnpm | 不可用，改用 npm |
| 可执行脚本 | 放置于内部目录执行，或通过 `bash script.sh` 显式调用 |
| 大量小文件 | 建议在内部目录完成处理后复制回共享存储 |

### 2.2 文件交付

工作区位于内部目录时，文件默认不对 Android 文件管理器可见。需要交付时：

- 单个文件：`dsh-android share <路径>`，将调起系统分享面板
- 批量或需长期保留：复制至 `/mnt/phone/<目标目录>/`

## 3. 环境限制

以下能力在本环境中不可用，相关问题无法通过配置解决：

- **文件沙箱**：bwrap 因 PRoot 拦截 `readlink(/proc/self/fd)` 无法运行；Landlock 因内核 ABI 不支持而不可用。两个后端均失效，应用仅能以 `danger-full-access` 模式运行。安装 bubblewrap 或调整 Landlock 均无效。
- **系统目录访问**：`/data`、`/system`、`/vendor`、`/dev/block` 及其他应用的 `Android/data` 均不可访问。
- **挂载操作**：容器内所有 `mount` 均由 PRoot 模拟（`CapEff=0`），不产生实际效果。
- **凭据文件**：`$DSH_HOME` 下的凭据文件权限受限，不可假定其可读。

---

## 4. Android 能力接口

`dsh-android` 命令行工具提供与 Android 系统的交互能力，一般情况下 `safe` 模式即可使用，无需开启 ADB 扩展：

```
ping / battery / device / clipboard-get / clipboard-set / toast / notify /
vibrate / openurl / share / perms / openperms / tts / tts-stop /
location / sensors / apps / adb
```

- 内部目录 → Android 设备：`dsh-android share <文件>` 或复制至 `/mnt/phone/`
- Android 设备 → 内部目录：需先经共享存储中转（当前未提供文件选择器），再行复制
- ADB `safe` 模式下不开放任意 shell（包括 `run-as`、`cp`、`ls`），仅支持白名单命令：`input`、`screencap`、`dumpsys`、`pm list`、`getprop`、`settings get`、`wm`

## 5. 页面白屏问题排查

本应用前端由官方 DSH 构建产物组成，使用了 Chrome 85 及以上的语法特性。
当系统 **Android System WebView 版本低于 85** 时，前端脚本在解析阶段即失败，不会执行任何语句，
表现为页面完全空白，但服务端运行正常。

### 5.1 判定方法

| 检查项 | 白屏时 | 正常时 |
|---|---|---|
| `boot.log` 中的 `PAGE_DONE` | 仍会输出，**不能作为判定依据** | 同样输出 |
| `web.log` 中的 `[DIAG]` 行 | `"pluginLoaded":false`、`"hasEditor":false`、`"sidebar":null` | `"pluginLoaded":true`、`"failed":0`、`sidebar.w > 0` |

判定应依据 `web.log` 中的 `[DIAG]` JSON 行，而非页面加载完成标记。

### 5.2 查询 WebView 版本

容器内无法直接读取 WebView 版本：Android 8 及以上版本对应用屏蔽 `/proc/net`，
查询其他应用包信息需要 shell 权限。可用的查询方式如下：

1. 由使用者在设备上查看：设置 → 应用 → 显示系统应用 → `Android System WebView` → 版本号
2. 已开启 ADB 扩展时（需先完成无线调试配对）：

   ```bash
   dsh-android adb exec shell "dumpsys webviewupdate | grep 'Current WebView package'"
   ```

   输出格式示例：`(com.google.android.webview, 155.0.8059.43)`

### 5.3 版本要求

| 语法或接口 | 最低要求 |
|---|---|
| `??=`、`\|\|=`、`&&=` 逻辑赋值运算符 | Chrome 85（语法级） |
| `String.prototype.replaceAll` | Chrome 85 |
| `Array.prototype.at` | Chrome 92 |
| `Object.hasOwn` | Chrome 98 |

逻辑赋值运算符属于语法特性，无法通过 polyfill 补齐：脚本在解析阶段即被拒绝，整个 `<script>` 块不会执行。
因此安装 polyfill、清除缓存、重新安装应用均无法解决此问题。

### 5.4 处理建议

1. 向使用者说明根本原因：应用本身无故障，问题源于系统 WebView 版本过低
2. 引导其更新「Android System WebView」：
   - 在应用商店搜索 `Android System WebView`
   - 部分定制系统可在「设置 → 应用管理 → 显示系统应用」中找到
3. 更新后无需重新安装本应用，重启应用即可生效
4. 若设备无法安装新版 WebView（系统已停止更新），应如实说明该设备不满足本应用的运行要求

## 6. 低版本 Android 的已知问题

以下问题已在本版本修复。若仍出现，说明设备安装的是旧版安装包。

| 现象 | 适用平台 | 原因 |
|---|---|---|
| 启动即崩溃，日志含 `NoSuchMethodError: ...Path.of` | Android 10 及以下 | `Path.of` 属于 Java 11 接口，Android 至 API 33 才提供 |
| 无法写入日志、目录无法创建、页面空白 | Android 10 | `requestLegacyExternalStorage` 配置导致 scoped storage 限制 `/sdcard` 写入 |

排查时可先确认系统版本：`getprop ro.build.version.release`

## 7. 高风险操作

以下操作必须获得使用者明确同意后方可执行：

`reboot`、`poweroff`、`shutdown`、`halt`（包括通过 `adb shell` 下发）、
格式化存储、卸载系统分区、删除系统目录、批量删除使用者数据。

> 说明：曾发生因执行 `adb shell 'reboot -p'` 导致设备关机的情况。
> 添加超时或管道不能替代确认步骤，命令一经下发即生效。

---

## 8. 安装包的行为边界

本安装包不会修改以下内容：

| 项目 | 说明 |
|---|---|
| `$DSH_HOME/AGENTS.md` | 使用者的全局指令文件，由使用者与 AI 助手共同维护，安装包无权改写 |
| `~/.agents/AGENTS.md` | 同上，属于使用者 |
| 使用者的 `workspace.json` | 工作区配置由 DSH 自身保存，安装包不介入 |
| 已安装插件与对话数据 | — |

安装包仅执行以下两项配置操作：

1. 补充 `documentsDirectory` 配置。缺少该配置时，官方代码会调用容器内不存在的 `xdg-user-dir`，
   导致默认工作区无法创建。
2. 预先创建默认工作区目录。

其他配置项均不修改。如确需变更配置，应先征询使用者意见。
