## 教训 L10 · 尺子错
- 标题: 从外部量不到 app 私有目录 —— 只能让容器自己报；就绪判据不能用 HTTP 首页
- 现象: 「启动容器」一段 43 秒，我猜是 proot 慢/rootfs 大；实测 proot 只占 3 毫秒。同时「已就绪」白等 12 秒。
- 根因: 我一直把「启动容器慢」当成 proot/rootfs 层面的问题（rootfs 376MB、501 个符号链接），从没量过。实测 result：proot 装配 3 毫秒、node exec 4 毫秒，剩下 99.8% 全在 DSH 加载模块。更关键的是：想从外部量 app 私有目录里的东西**根本量不到** —— `adb shell` 读不了 `/data/data/.../files/lib`，`run-as` 对 release 包无效，而 ADB full 模式给的是 shell 权限，不是 app uid 权限，权限模型不同，混不了。所以正确姿势只有一条：让容器自己报时间戳（改启动命令 echo，落在已被读取的 stdout 里）。
- 正解: 在容器启动命令里埋 `T+` 时间戳（`date +%s%N` 差分 + 关键节点 echo），Java 侧按 `line.startsWith("T+")` 捞进 boot.log。结论：proot 3ms / node exec 4ms / DSH 加载约 29s。另顺带发现就绪判据用错了 —— probe() 打 `GET /`（首页 HTML）且 readTimeout 2s，白等 12 秒；改成只建 TCP 连接的 isPortOpen() 后降到 0.01s。
- 适用范围: 要测量「app 私有目录里的东西」或「容器内某阶段耗时」时；以及给启动挑就绪判据时
